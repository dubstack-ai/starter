# Quickstart

Start with a working docs site, make one real customization, preview it, and publish the change through the same Git-backed flow your team will use in production.

## Before you begin

You need:

- A DubStack site created during onboarding
- A documentation repository connected to the site, or a hosted starter repository created by the skip-Git flow

<Callout type="info">
  If you skipped Git setup during onboarding, start in the web editor first. You can connect your own repository later from Git settings without changing the content model.
</Callout>

## Make your first change

Choose the path that matches how you want to work.

<Tabs>
  <Tab title="Web editor">
    <Steps>
      <Step title="Open the editor">
        From the dashboard, open your site and select **Editor**.
      </Step>

      <Step title="Update the introduction">
        Open **Introduction** and update the `description` in the frontmatter.

        ```mdx
        ---
        title: Introduction
        description: "Your custom product description"
        ---
        ```
      </Step>

      <Step title="Publish the change">
        Click **Publish** in the editor toolbar. The change is committed to your configured docs source and synced to your live site.
      </Step>

      <Step title="Verify the deployment">
        Return to **Home** in the dashboard and wait for the deployment activity to finish. Open your live docs site and confirm the new description is visible.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Git editor">
    <Steps>
      <Step title="Clone your docs repository">
        Clone the repository connected to your DubStack site.

        ```bash
        git clone <your-docs-repo-url>
        cd <your-docs-repo>
        ```
      </Step>

      <Step title="Edit a page">
        Open `index.mdx` and update the frontmatter description or the first content block.
      </Step>

      <Step title="Check the diff">
        Review the exact files you changed before publishing.

        ```bash
        git diff -- index.mdx dubstack.json
        git diff --check
        ```
      </Step>

      <Step title="Commit and push">
        Push the change to the branch connected to your DubStack site.

        ```bash
        git add index.mdx
        git commit -m "Update introduction"
        git push
        ```
      </Step>

      <Step title="Verify the deployment">
        Check the dashboard activity feed, open the live site, and confirm the rendered page matches your change.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Wire the API reference

This starter includes a working BeatBox OpenAPI example so the API reference and playground are usable immediately.

<Steps>
  <Step title="Open the bundled spec">
    Review `api-reference/openapi.json` to see how endpoint pages and playground requests are generated.
  </Step>

  <Step title="Replace it with your API">
    Swap in your own OpenAPI document when you are ready. Keep the file path stable unless you also update `dubstack.json`.
  </Step>

  <Step title="Check the generated pages">
    Open [API documentation](/api-reference/introduction) and the [API playground](/api-reference/openapi) to confirm the reference renders correctly.
  </Step>
</Steps>

<Callout type="note">
  Keep `dubstack.json`, MDX pages, images, snippets, and OpenAPI specs in Git. DubStack reads the published site from the synced content artifacts, so the repository remains the source of truth.
</Callout>

## Validate before sharing

Run these checks before sending the site to your team or customers:

- The homepage and quickstart no longer contain starter-only copy
- Navigation links resolve on the live site
- `dubstack.json` references the right pages and OpenAPI spec
- The API playground loads the expected base URL, endpoint list, and examples
- Search, assistant answers, and public MCP reads return useful content instead of placeholder guidance

<Callout type="tip">
  If you are working locally, run `git diff --check` before pushing. If you are working in the dashboard, use the deployment activity on Home to confirm the publish completed.
</Callout>
