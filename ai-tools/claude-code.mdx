Use Claude Code to draft and review documentation in your local repository. Published changes still follow the connected Git workflow.

## Prerequisites

- Claude Code installed and authenticated
- Your documentation repository cloned locally
- A published docs site if you want Claude Code to search the live content

## Setup

<Steps>
  <Step title="Open the docs repository">
    Start Claude Code from the directory that contains `dubstack.json`.

    ```bash
    cd path/to/your-docs
    claude
    ```
  </Step>

  <Step title="Review the project instructions">
    This starter includes an `AGENTS.md` file with repository structure, writing standards, safety rules, and review checks.

    Add a `CLAUDE.md` file only when Claude Code needs instructions that are more specific than the shared project guidance.
  </Step>

  <Step title="Connect the public docs MCP">
    Add your published docs site as a Streamable HTTP MCP server.

    ```bash
    claude mcp add --transport http my-docs https://your-docs-domain.com/mcp
    ```

    For a site mounted under `/docs`, use the mounted endpoint:

    ```bash
    claude mcp add --transport http my-docs https://your-domain.com/docs/mcp
    ```
  </Step>

  <Step title="Verify the connection">
    ```bash
    claude mcp list
    ```

    Ask Claude Code to search the published docs before proposing a local change.
  </Step>
</Steps>

## Public MCP boundary

The public MCP server is read-focused. It can search and read published pages, and it can submit documentation feedback when that add-on is enabled.

It does not edit repository files, change navigation, update themes, or grant dashboard access. Make authoring changes in the local repository and publish them through Git.

## Example prompts

```text
Use the docs MCP to find the current authentication guide, then review the
local MDX page for missing prerequisites or conflicting instructions.
```

```text
Review my changed MDX files for missing frontmatter, broken relative links,
and navigation entries that need to be updated in dubstack.json.
```

## Publish changes

1. Review the local diff.
2. Commit the documentation changes.
3. Push to the connected branch or open a pull request.
4. Wait for the deployment to complete.
5. Verify the rendered page and public MCP results.
