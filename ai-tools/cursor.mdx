Use Cursor to draft and review MDX documentation in your local repository.

## Prerequisites

- Cursor installed and authenticated
- Your documentation repository cloned locally
- A published docs site if you want Cursor to search the live content

## Setup

<Steps>
  <Step title="Open the docs repository">
    Open the directory that contains `dubstack.json`.
  </Step>

  <Step title="Add project rules">
    Create `.cursor/rules/docs.mdc` and keep the rule focused on your repository.

    ```md title=".cursor/rules/docs.mdc"
    # Documentation project

    - Pages are MDX files with YAML frontmatter.
    - Navigation and site settings live in `dubstack.json`.
    - Use second-person instructions and sentence-case headings.
    - Prefer relative links for internal pages.
    - Never add secrets, private customer data, or unverified product behavior.
    - Review the diff before publishing through Git.
    ```

    Use the starter's `AGENTS.md` as the shared source for writing and safety rules.
  </Step>

  <Step title="Connect the public docs MCP">
    Add a Streamable HTTP server in Cursor's MCP settings.

    ```json
    {
      "mcpServers": {
        "my-docs": {
          "url": "https://your-docs-domain.com/mcp"
        }
      }
    }
    ```

    For a path-mounted site, use `https://your-domain.com/docs/mcp`.
  </Step>

  <Step title="Review and publish">
    Use Cursor to edit local files, then review, commit, and push the changes through the connected Git workflow.
  </Step>
</Steps>

## Example prompts

```text
Use the docs MCP to find related published pages before editing this local
guide. Avoid duplicating an existing explanation.
```

```text
Review this MDX page for missing frontmatter, unclear headings, broken
relative links, and unsupported component syntax.
```
