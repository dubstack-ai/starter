<Callout type="info">
**Prerequisites**:
- Git
- A documentation repository with a `dubstack.json` file
</Callout>

Use local editing when you want full control over branches, reviews, and commit history. DubStack still reads from the synced repository, so local changes become visible after you push and the site finishes deploying.

<Steps>
<Step title="Clone the docs repository">

```bash
git clone <your-docs-repo-url>
cd <your-docs-repo>
```
</Step>

<Step title="Create a branch">

```bash
git switch -c docs/update-quickstart
```
</Step>

<Step title="Edit content and configuration">

Update MDX pages, images, snippets, or `dubstack.json`.

- Use `index.mdx` for the homepage
- Use `quickstart.mdx` for the first success path
- Use `dubstack.json` for navigation, theme, anchors, and tabs
- Use `api-reference/openapi.json` for API reference generation
</Step>

<Step title="Review the diff">

```bash
git diff
git diff --check
```

Fix whitespace errors, broken paths, and accidental changes before committing.
</Step>

<Step title="Commit and push">

```bash
git add .
git commit -m "Update docs"
git push -u origin docs/update-quickstart
```

</Step>
</Steps>

## Verify the deployment

After pushing, open the dashboard Home page and watch the deployment activity. When the deployment finishes, open the live docs site and check:

- The changed page renders correctly
- Sidebar and header links still resolve
- Code blocks and MDX components render as expected
- API reference pages still match the OpenAPI spec
- Search, assistant answers, and public MCP reads return the updated content

## Use the web editor for rendered previews

If you need a rendered preview before pushing from your local branch, open the same page in the dashboard editor. The editor lets you inspect the rendered MDX and publish through the same Git-backed flow.

<Callout type="note">
  Keep Git as the source of truth. Use the dashboard editor for rendered checks and quick edits, then rely on the deployment activity to confirm the synced version is live.
</Callout>

## Code formatting

We suggest using IDE extensions that recognize and format MDX. If you're a VS Code user, consider the [MDX extension](https://marketplace.visualstudio.com/items?itemName=unifiedjs.vscode-mdx) for syntax highlighting, and [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) for code formatting.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The deployment did not pick up my change">

    Confirm you pushed to the branch connected to your DubStack site, then check the dashboard deployment activity for the latest sync status.
  </Accordion>

  <Accordion title="A page is missing from navigation">

    Add the page to `dubstack.json`, commit the config change, and push again. Pages can exist in Git without being visible in navigation.
  </Accordion>
</AccordionGroup>
